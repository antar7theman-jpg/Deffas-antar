# خطة المزامنة الفورية الشاملة لمخزون السلع وصورها بين المدير والعمال عبر Firebase

تهدف هذه الخطة إلى تمكين المزامنة اللحظية التلقائية بالخلفية لبيانات المخزون والسلع وصورها وعمليات البيع والشراء بين المدير المستقل والأجهزة الخاصة بالعمال التابعين له فوراً ودون أي تأخير، مع ضمان عدم تعارض الكميات وتوفير تجربة عمل متكاملة متصلة بالإنترنت ومحلية (Offline-First).

---

## 1. تحليل الوضع الحالي ونقاط الربط

- **الوضع الحالي:**
  - يتم تخزين السلع والمنتجات محلياً في قاعدة بيانات Room عبر `ProductDao` و`AntarRepository`.
  - العمليات التي تتم في شاشات نقطة البيع (POS) وإضافة السلع وشراء الفواتير تقوم بخصم أو إضافة المخزون محلياً فقط.
  - صور السلع يتم حفظها كمسارات ملفات محلية على الهاتف الذي التقطها (`/data/user/0/.../prod_img_xxx.jpg`)، وبالتالي لا يمكن للأجهزة الأخرى الوصول إليها مباشرة دون مزامنة ثنائية.
  - يوجد هيكل أمان سحابي في `firestore.rules` يسمح للمدير والعمال المعتمدين (`isApprovedStaff()`) بقراءة وتعديل السلع في مسار السلع التابع للمدير.

- **الهدف المستقبلي:**
  - مزامنة سحابية فورية تلقائية لحظية بالخلفية عبر مستمعي Firestore (`SnapshotListener`) تعمل في الخلفية لكل من المدير وعماله.
  - ضغط صور السلع بدقة عالية وجودة محسنة وتحويلها إلى كود Base64 مدمج سحابياً، مع تنزيلها وتخزينها في الكاش المحلي لهواتف العمال تلقائياً بمجرد إضافة السلعة.
  - مزامنة حركات المخزون (خصم الكميات عند إتمام البيع، أو زيادتها عند الشراء أو التزويد) لحظياً عبر جميع الأجهزة مع منع التعارض والبيع المزدوج لنفس الكميات.

## 2. الهيكلية التقنية وخريطة المزامنة (Architecture & Sync Flow)

```
[هاتف المدير المستقل]                         [Firebase Firestore]                     [هاتف العامل التابع]
┌─────────────────────────┐               ┌──────────────────────────┐               ┌─────────────────────────┐
│ 1. إضافة أو تعديل سلعة  │               │ collection("users")      │               │ 3. استقبال السلعة فوراً │
│    + التقاط صورة السلعة │ ── PUSH ────> │   .doc(managerUid)       │ ── REALTIME ─>│    تلقائياً بالخلفية    │
│    (ضغطها وتحويلها Base64)               │   .collection("products")│    LISTENER   │    حفظها في Room المحلي │
└─────────────────────────┘               └──────────────────────────┘               │    تخزين الصورة بالكاش  │
                                                        ▲                            └─────────────────────────┘
                                                        │                                         │
[أي هاتف: بيع أو شراء]                                 │                                         ▼
┌─────────────────────────┐                             │                            ┌─────────────────────────┐
│ 2. إتمام عملية بيع/شراء │                             │                            │ شاشة الكاشير (POS)      │
│    تحديث فوري للمخزون   │ ── ATOMIC BATCH UPDATE ─────┘                            │ تنعكس الكمية بـ 0ms     │
└─────────────────────────┘                                                          └─────────────────────────┘
```

## 3. خطة المهام التفصيلية للتنفيذ

### المرحلة 1: معالجة وضغط وتشفير صور السلع السحابية والمحلية
1. **إنشاء مساعد معالجة الصور السحابية (`ProductCloudImageHelper`):**
   - وظيفة ضغط صورة المنتج عند حفظها (أبعاد قصوى 384x384 مع نسبة جودة JPEG 80%) لإنتاج بايتات مضغوطة للغاية (~15 إلى 25 كيلوبايت).
   - تحويل الصورة المضغوطة إلى Base64 Data URL وتخزينها في حقل `imageUrl` للمنتج في Firestore.
   - وظيفة فك التشفير التلقائي: عندما يستلم هاتف العامل سجلاً يحتوي على `imageUrl` المشفرة، يتم تحويلها إلى ملف صورة محلي في مجلد الكاش وحفظ مساره في `imagePath`، مما يتيح لمكتبة Coil ومكونات العرض إظهار الصورة فوراً.

### المرحلة 2: خدمة المزامنة اللحظية التلقائية للمخزون بالخلفية (`LiveInventorySyncManager`)
1. **بناء خدمة المراقبة والمزامنة السحابية:**
   - تحديد المعرف السحابي المشترك للمخزون:
     - إذا كان الحساب الحالي **مديراً**: استخدام `userId` الخاص به.
     - إذا كان الحساب **عاملاً تابعاً**: استخدام `parentManagerUid` التابع لمديره.
     - إذا كان **مالكاً**: استخدام معرف المتجر أو المالك.
   - تشغيل `SnapshotListener` على مسار `users/{managerId}/products`:
     - عند إضافة سلعة جديدة أو تعديل سعر أو اسم أو باركود بواسطة المدير: تنعكس التغييرات فوراً في Room لدى العامل.
     - معالجة الحذف الناعم (`isDeleted`).
     - دمج السلع الذكي مع منع استبدال التعديلات الأحدث محلياً في حالة انقطاع الإنترنت.

### المرحلة 3: مزامنة حركات المخزون عند البيع والشراء
1. **تحديث `saveProduct` في `AntarSalesViewModel`:**
   - عند قيام المدير بحفظ أو تعديل سلعة: حفظها في Room ورفعها فوراً إلى Firestore (`users/{managerId}/products/{docId}`) مع الصورة المضغوطة.
2. **تحديث `completeCheckout` (عمليات البيع):**
   - عند إتمام الفاتورة لدى الكاشير (العامل أو المدير):
     - خصم الكميات في Room محلياً لسرعة العرض الفورية.
     - إرسال تحديثات الكميات المخصومة إلى Firestore عبر `WriteBatch` لضمان التزامن ومنع التعارض.
3. **تحديث `createPurchaseInvoice` و`quickRestockProduct` (عمليات الشراء والتزويد):
   - عند إدخال فاتورة مشتريات جديدة أو تزويد سريع للسلعة، يتم رفع رصيد المخزون الجديد مباشرة إلى Firestore ليظهر فورياً لدى العاملين.

### المرحلة 4: مؤشر حالة الاتصال والمزامنة الحية في واجهات البيع والمخزون
1. **إضافة شارة المزامنة اللحظية في شريط الـ TopAppBar وشاشة المخزون:**
   - توضيح حالة مزامنة المخزون مع السيرفر: "المخزون متزامن لحظياً ⚡" مع وقت آخر حركة مزامنة.
   - تنبيه العمال عند وصول سلع جديدة أو تعديل في الأسعار والمخزون من قبل المدير.
