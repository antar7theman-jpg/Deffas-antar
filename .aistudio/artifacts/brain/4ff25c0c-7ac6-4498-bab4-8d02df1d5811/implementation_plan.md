# تحديد واختيار الفاتورة المسددة عند تسديد دفعة العميل

إتاحة إمكانية تحديد واختيار الفاتورة المسددة بدقة عبر قائمة منسدلة ذكية داخل نافذة تسديد دفعة العميل، مع التعبئة التلقائية لقيمة الفاتورة وتوثيق رقمها في الملاحظات ووصل القبض وسند الطباعة الحرارية وPDF.

## قرارات المستخدم المعتمدة

> [!IMPORTANT]
> تم تأكيد الخيارات التالية بناءً على إجاباتك في الخطوة التمهيدية:

- **طريقة عرض واختيار الفاتورة**: قائمة منسدلة (Dropdown) أنيقة داخل نافذة تسديد الدفعة تعرض الفواتير الآجلة غير المسددة الخاصة بالعميل.
- **الإجراء التلقائي عند الاختيار**:
  1. تعبئة حقل المبلغ تلقائياً بقيمة الفاتورة المختارة (أو الرصيد المتبقي المستحق).
  2. توثيق رقم الفاتورة في حقل الملاحظات تلقائياً (مثال: `سداد فاتورة مبيعات #INV-912989`).
  3. توثيق رقم الفاتورة المسددة كمرجع رسمي داخل وصل السند المطبوع (حرارياً وعبر PDF) وعند المشاركة.
  4. الإبقاء على خيار "سداد عام لحساب المديونية" لمن يرغب في تسديد مالي عام لا يخص فاتورة بعينها.

---

## 1. نظرة عامة وتجربة المستخدم

### ما يقدمه التحديث
- عند الضغط على **تسديد دفعة** لأي عميل (من شاشة حركة الديون أو بطاقة العميل أو جدول الحركات):
  - تظهر القائمة المنسدلة الجديدة: **"الفاتورة المراد تسديدها"**.
  - تسرد القائمة جميع الفواتير الآجلة المسجلة للعميل مرتبة من الأحدث للأقدم مع رقم الفاتورة وقيمتها وتاريخها.
  - خيار افتراضي مرن: **"سداد عام لحساب المديونية (بدون تخصيص فاتورة)"**.
- عند اختيار أي فاتورة:
  - يُعبأ حقل المبلغ فوراً بقيمة الفاتورة المحددة دون الحاجة لكتابتها يدوياً.
  - يُحدث حقل الملاحظات تلقائياً ليحمل صيغة واضحة برقم الفاتورة.
  - يتم حفظ الفاتورة المحددة وتمريرها لسند القبض المالي (`DebtPaymentReceiptData`).
  - يعرض الوصل المطبوع (المعاينة، الورق الأبيض، الطباعة الحرارية البلوتوث، والـ PDF) سطر تمييز واضح: **"الفاتورة المسددة: #رقم_الفاتورة"**.

## 2. المظهر والتصميم المرئي (UI / Material Design 3)

```
┌────────────────────────────────────────────────────────┐
│  تسديد دفعة من العميل: [اسم العميل]                   │
├────────────────────────────────────────────────────────┤
│  [ الرصيد السابق المستحق: 132.00 د.ج ]                 │
│                                                        │
│  ▼ الفاتورة المسددة (اختياري):                          │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 🧾 فاتورة مبيعات #INV-912989  (132.00 د.ج)      ▼ │  │
│  └──────────────────────────────────────────────────┘  │
│    ├─ سداد عام لحساب المديونية                         │
│    └─ 🧾 فاتورة مبيعات #INV-912989 (132.00 د.ج)        │
│                                                        │
│  المبلغ المحصل (د.ج): [ 132.00 ]                       │

│                                                        │
```

- **القائمة المنسدلة**: تصميم حديث مطابق لمعايير Material 3 بحواف دائرية (12dp) وأيقونة تمييزية `ReceiptLong` مع قائمة منبثقة واضحة الخيارات.
- **التفاعل الفوري**: تحديث حي للمبلغ المحسوب والرصيد المتبقي المتوقع بعد السداد.
- **بطاقة الوصل والسند**: إبراز الفاتورة المسددة في المعاينة والوصل المطبوع باللون الأخضر المميز.

## 3. القرارات التقنية وهيكلية البيانات

1. **نموذج خيارات الفواتير الآجلة للعميل**:
   - استخراج وتجميع الفواتير الآجلة للعميل من قائمة `archivedInvoices` وحركات المديونية `customerTransactions`.
   - استخلاص الفواتير التي تمت بنمط دين أو المتبقية كذمة مالية مرتبطة بكود الفاتورة.
2. **تمرير مرجع الفاتورة إلى سند القبض**:
   - دعم حقل `invoiceReference: String? = null` في كائن `DebtPaymentReceiptData`.
   - توثيقه في نص المشاركة السريعة عبر واتساب/ماسنجر، وتوثيقه في ترويسة سند القبض الحراري وPDF.
3. **التكامل غير المعطل**:
   - الحفاظ التام على إمكانية التسديد العام دون اشتراط اختيار فاتورة، لضمان عدم تعطل المستخدم إذا كانت المديونية قيداً افتتاحياً أو مديونية يدوية.
